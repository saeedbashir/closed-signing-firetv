## What in the spec turned out to be wrong or underspecified

1. **YOLOv8n.** The spec named it; `ultralytics` and its weights are AGPL-3.0, incompatible with
   shipping under Apache 2.0. Switched to YOLOX-Tiny (Apache 2.0, weights are release assets of
   the same repository). Spec updated.
2. **"Lifting them out leaves a hole where their box was."** On a real picture-in-picture, the
   interpreter stands in a *window* with its own backdrop. Cutting the person's box would leave a
   floating rectangle of backdrop in the main video, and `delogo` would streak backdrop pixels
   into the patch. The first spike frame showed exactly this. Added `grow_window`: each edge of
   the person box steps outward while the band just outside is temporally static and continuous
   in mean grey with the band just inside, stopping at the window border, capped at 75% of the
   box per side, then padded 3%. The manifest's `cropRect` is therefore the window, which is also
   what the signer layer should show. **Needs tuning on real clips Saturday** — the thresholds
   (`window_*` in `config.py`) are guesses.
3. **`ffmpeg-python`.** Replaced with a subprocess wrapper; one fewer dependency and the filter
   graphs are readable in one file. Recorded in `DEPENDENCIES.md`.
4. **Fill.** ffmpeg's `delogo` refuses rectangles touching the frame edge (inset by 2 px) and
   `boxblur` caps its radius by the chroma plane, so the comparison blur uses `gblur`. The
   interpolated patch shows directional streaks when the border pixels are busy; on a real clip
   the border is programme footage, so Saturday will tell whether it reads as acceptable. If not,
   the next honest option is a blurred *copy of the surrounding footage* rather than interpolation.
5. **Manual crops carry `confidence: 1.0`.** The spec did not say what confidence a hand-drawn
   rectangle has. A human-verified rect is the strongest signal we have, so 1.0 with
   `method: manual-crop` making the provenance of the number explicit.
6. **Vega SDK 0.24 ships React Native 0.83.** The spec's version claim checks out against the
   release notes; no change needed.

### What in the spec turned out to be wrong or underspecified

7. **"Amazon Bedrock — generates the simplified caption track."** True but far too thin to
   build from. The spec never said what happens when the model drops a cue, and that is the
   only question that matters: a caption track that silently loses a line is worse than one
   that stays verbatim. Now: one retry narrowed to the missing cues, then those cues keep
   their original text, and the run reports coverage rather than claiming success. If not a
   single cue comes back, no simplified track is written at all.

8. **Structured outputs are not available on the Bedrock Messages endpoint.** The obvious
   implementation — a JSON schema guaranteeing one object per cue — is unsupported there.
   The cue protocol is therefore plain `[n]` markers that the pipeline validates itself.
   This turned out better anyway, since the fallback logic was needed regardless.

9. **The IAM action is `bedrock-mantle:CreateInference`, not `bedrock:InvokeModel`.** Current
   Claude models are served by the Messages API endpoint, which authorises a different
   action entirely. A policy written from memory would have failed at runtime. The resource
   ARN template for that endpoint is undocumented — see `friction-log/002`.

10. **Four stacks as planned, but not the planned four.** Putting the assets bucket in the
    storage stack and the distribution in the delivery stack is a CloudFormation dependency
    cycle: the origin access control adds a bucket policy that references the distribution.
    Caught by `cdk synth`. The assets bucket now lives with the CDN that serves it, which is
    the more honest grouping — it exists to be served.

11. **`ultralytics` was not the only licence trap.** Worth repeating the rule that caught it:
    check the weights licence separately from the code licence. Recorded for YOLOX in
    `CONTENT-LICENCES.md`.

### Found and fixed: two real bugs in layout handling

Built a synthetic corpus of six interpreted-broadcast layouts with exact known
rectangles, and ran the pipeline against it. Two failures, same root cause:

1. **Layout was classified from the person's box, not the window.** "Flush
   against a frame edge" is a property of the window; a person standing inside a
   side panel has margin on both sides and is never flush. Both side-panel clips
   were misread as corner insets, which would have patched a hole in the middle
   of a strip instead of cropping the strip away. Growth now runs before
   classification.
2. **Window growth used the band just inside the edge as its reference.** That
   band is the person's head, which is not the colour of the backdrop behind it,
   so vertical growth stopped at the first step. Each edge now carries its own
   running reference seeded from the first band it accepts, so growth follows
   the backdrop outward and stops at the step onto the programme.

After both: **6/6 layouts correct**, side panels at 0.96 and 0.97 IoU. The decoy
clip — a large still anchor beside a small signing inset — picks the signer on
motion ratio 3.27 with confidence 1.00, which is the first real evidence that
the heaviest-weighted signal in the heuristic does its job.

### Tuned one threshold on evidence

`window_mean_delta` was 20. Swept it across the corpus: 4 and 6 classify every
layout correctly, 8 lets growth walk off a dark backdrop onto a calm programme
(the step between them is only ~10 grey levels). Set to 6, the top of the
verified range. Recorded in the config with the numbers, so the next person to
touch it knows what it was chosen against.

### The validation harness now runs

It had no data. `harness/make_corpus.py` generates the corpus **and** writes
`ground_truth.yaml`, so `stm harness score` works today:

```
4/5 pass at IoU >= 0.85; mean IoU 0.902
```

Two things worth knowing before trusting a synthetic corpus: a drawn figure
gives **zero** detections, and a whole photograph is little better, because the
pixels around the detected person are more photograph. The person has to be
cropped tightly onto a flat backdrop.

### New: `stm triage`

Ranks candidate clips by how good a demo they will make, in about a second each.
Reports layout, extraction confidence, and a **fill difficulty** score measured
from the ring around the window: spatial detail decides whether the patch smears
in a still frame, temporal variance decides whether it flickers between frames.
Side panels score zero because a strip is removed, not patched.

`--sources` prints `sources.yaml` skeletons with the measurable fields filled in
and every judgement left blank. It does not touch licence, production credit or
acquisition route, and it says so in its own output.

Verified against the fill previews: clips it calls "good" fill invisibly, clips
it calls "marginal" smear visibly. The spec's first selection criterion is now a
number instead of an eyeball.

### Corrections to earlier work

14. **There IS a dropped-frame API.** I built an advance-rate proxy believing
    none existed. `VideoPlayer.getVideoPlaybackQuality()` returns
    `droppedVideoFrames`, `totalVideoFrames` and `corruptedVideoFrames`. It is
    in the shipped type definitions, not on the docs page I read. The probe now
    measures drop rate directly and keeps advance rate as a second signal,
    because the two fail differently: a starved decoder drops frames while the
    clock runs, a stalled one freezes the clock while dropping nothing.

15. **Media services go under `[wants]`, not `[needs]`.** My first manifest had
    them under `[needs]`, which declares a hard device requirement and narrows
    Appstore install targeting. Verified against `AmazonAppDev/vega-video-sample`.
    That sample also declares `com.amazon.inputd.service` for remote button
    events, which this product cannot do without.

16. **The probe had a type error.** `PressableStateCallbackType` carries
    `pressed`, not `focused`, so TV focus needs `onFocus`/`onBlur`.

17. **A passing exit code proved nothing.** The first build "exited with code 0"
    while actually failing — the error was swallowed in the npm script chain,
    and only the absence of a `.vpkg` revealed it. Verify by artifact.

18. **My own manifest merge was the first build failure**, not the SDK's fault:
    the script split on the literal text `[wants]`, which also appeared inside a
    comment, splicing prose in as a table header.

## Session 4 addendum — Experiment 2 ANSWERED

Saeed pushed back on my claim that the device had no internet. He was right: my

### Result: PASS on the emulator

| Phase | main | signer |
| --- | --- | --- |
| baseline | 0.99–1.01, readyState 3 | — |
| signer added | **0.99–1.01, unchanged** | 0.99–1.01, readyState 3 |
| both seek +10s | recovers to 1.01 | recovers to 1.01, in sync |

Main did not degrade when the second surface started. That is the measurement
the gate asked for.

**Four caveats, all in `experiments/e2-two-decoders/STATUS.md`:** it is the
emulator not hardware; `getVideoPlaybackQuality()` returns 0/0 there so drop
rate is unmeasured and the advance-rate "proxy" is what actually produced the
result; sink warnings mean on-screen rendering of both layers is unconfirmed;
and the sources were two 720p clips rather than 1080p plus a small signer.

### The rule that cost two hours

**Vega's media player refuses plain HTTP.**

```
MediaPlayerUtils.cpp isUriSchemeSecure
Got an insecure protocol/scheme http, return error
```

Reported to JavaScript as `MEDIA_ERR_SRC_NOT_SUPPORTED`, which reads like a
codec problem. Four source forms tried; only HTTPS works. Local paths fail for
a separate reason: the app runs in its own mount namespace, so a file pushed
with `copy-to` to `/tmp` is not the `/tmp` the app sees.

**This changes the bundled-catalogue plan.** The spec assumed the app could
play a local bundled file with no network. It cannot, at least not by path.
Assets must be served over HTTPS, which the CloudFront distribution in `infra/`
already does. Revisit before relying on an offline demo.

### One process mistake worth recording

I read a summary off the log and nearly reported it as the result. It was the
*previous* app instance, still running and idling, because I never terminated
it. The readings interleave and look plausible. Terminate before relaunching,
and filter the log by PID.

### Corrections to my own earlier claims

19. **"Outbound internet from the device is blocked" was wrong.** A byte-range
    request returned 403 and I generalised from one test. The device reaches
    the internet fine.
20. **`getVideoPlaybackQuality()` does not work on the emulator.** I switched
    the probe to it as the primary instrument on the strength of the type
    definitions. It returns 0/0. The advance-rate metric I had described as a
    proxy is the one that produced the answer.
